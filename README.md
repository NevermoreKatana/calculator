# 🍫 Ganache Calculator

Расчёт рецептур ганаша, шоколадных конфет и кондитерских начинок: состав,
вода, сахара, сухая масса, активность воды и теоретическая оценка срока
годности.

Модель расчёта восстановлена из книги
`формирование ганаша программа.xlsx` — включая разбор и починку повреждённых
формул `#REF!`. Подробности: **[docs/calculation-model.md](docs/calculation-model.md)**.

Научное обоснование расчётного ядра — исследование литературы на трёх языках,
сравнение моделей, валидация и ограничения:
**[docs/scientific-research/](docs/scientific-research/FINAL-REPORT.md)**.

## Главный принцип

Приложение никогда не выдаёт отсутствие данных за наличие формулы.

* Состав рецепта считается **точно**.
* `a_w` рассчитывается **по составу водной фазы** (мультисолютное уравнение
  Норриша), а не выводится из процента воды. Результат — **интервал** с
  указанием уверенности; измеренное значение всегда имеет приоритет.
* Микробиологические пороги хранятся **по организмам** с источниками и с
  расхождениями между источниками, а не как полосы на картинке.
* Барьеры стабильности перечисляются со статусом каждого; скорость роста
  микроорганизмов **не рассчитывается** — кардинальные параметры для ганаша
  не опубликованы.
* Срок годности — **только** эмпирические контрольные точки и документированная
  интерполяция между ними; вне области наблюдений выводится
  «недостаточно данных», а не выдуманное число.
* Каждая научная константа обязана ссылаться на зарегистрированный источник;
  это **проверяется тестами**.

## Стек

## Быстрый старт

```bash
npm install
cp .env.example .env          # укажите DATABASE_URL и DIRECT_DATABASE_URL
npm run db:push               # создать схему
npm run import:excel          # загрузить 113 ингредиентов из книги Excel
npm run dev
```

Открыть <http://localhost:3000>.

### Скрипты

| Команда | Назначение |
|---|---|
| `npm run dev` | Дев-сервер |
| `npm run build` | Продакшен-сборка |
| `npm test` | Тесты движка расчёта (87) |
| `npm run typecheck` | Проверка типов |
| `npm run lint` | ESLint |
| `npm run db:push` | Применить схему Prisma |
| `npm run db:studio` | Prisma Studio |
| `npm run import:excel` | Импорт листа `Database` |
| `npm run import:excel -- --dry-run` | Разбор с отчётом, без записи в БД |

Импортёр читает `.xlsx` **без внешних зависимостей** (собственный ZIP+XML
парсер на `node:zlib`) — пакет `xlsx` из npm не используется из-за неустранённых
уязвимостей высокого уровня.

## Локальный запуск в контейнере

Требуется Docker с Compose v2+. Отдельно поднимать PostgreSQL не нужно —
он входит в стек.

```bash
docker compose up -d --build
```

Открыть <http://localhost:3000>.

Что происходит при запуске:

1. `db` — PostgreSQL 16, поднимается и ждёт `pg_isready`;
2. `migrate` — одноразовый контейнер: `prisma db push`, затем импорт 113
   ингредиентов из книги Excel, после чего завершается с кодом 0;
3. `app` — стартует только после успешного завершения `migrate`.

### Команды

| Команда | Назначение |
|---|---|
| `docker compose up -d --build` | Собрать и запустить |
| `docker compose ps` | Статус и healthcheck |
| `docker compose logs -f app` | Логи приложения |
| `docker compose logs migrate` | Отчёт импорта Excel |
| `docker compose down` | Остановить (данные сохраняются) |
| `docker compose down -v` | Остановить и **удалить БД** |
| `docker compose exec db psql -U ganache -d ganache_calculator` | psql внутри контейнера |

### Порты

| Сервис | Хост | Причина |
|---|---|---|
| `app` | `3000` | — |
| `db` | **`5433`** | 5432 может быть занят локальным PostgreSQL |

Подключение к контейнерной БД снаружи:
`postgresql://ganache:ganache@localhost:5433/ganache_calculator`

### Устройство образа

* Многостадийная сборка: `base → deps → builder → runner`.
* Рантайм использует `output: 'standalone'` — в образ попадает только сервер и
  реально используемые зависимости (**463 МБ** против 1.78 ГБ у стадии сборки).
* Приложение работает от непривилегированного пользователя `nextjs` (uid 1001).
* `HEALTHCHECK` опрашивает `/calculator`, поэтому `docker compose ps` показывает
  не «процесс жив», а «приложение отвечает».
* Стадия `builder` переиспользуется сервисом `migrate`: Prisma CLI, `tsx` и
  исходная книга Excel нужны для импорта, но не нужны в рантайме.
* Данные лежат в именованном томе `db-data` и переживают `docker compose down`.
* Импорт идемпотентен (upsert), повторный запуск не создаёт дублей.

Пароли в `docker-compose.yml` — заведомо тривиальные и предназначены только для
локального стенда; для публичного развёртывания их нужно заменить.

## Деплой на Vercel

Docker и отдельный сервер не нужны.

1. **База данных.** Создайте PostgreSQL — Vercel Postgres, Neon или Supabase.
2. **Импорт.** Экспортируйте строку подключения и загрузите ингредиенты:

   ```bash
   export DATABASE_URL="postgresql://…"
   export DIRECT_DATABASE_URL="postgresql://…"   # непулированная строка
   npm run db:push
   npm run import:excel
   ```

3. **Проект.** Импортируйте репозиторий в Vercel. Framework Preset — Next.js,
   команды сборки менять не нужно.
4. **Переменные окружения** (Project → Settings → Environment Variables):

   | Переменная | Обязательна | Комментарий |
   |---|---|---|
   | `DATABASE_URL` | да | Пулированная строка для рантайма |
   | `DIRECT_DATABASE_URL` | да | Непулированная — для миграций |
   | `OPEN_FOOD_FACTS_BASE_URL` | нет | По умолчанию `https://world.openfoodfacts.org` |
   | `EXTERNAL_LOOKUP_TIMEOUT_MS` | нет | По умолчанию `6000` |

5. **Deploy.** `postinstall` запускает `prisma generate` автоматически.

При пулере (Neon/Supabase/PgBouncer) добавьте в `DATABASE_URL`
`?pgbouncer=true&connection_limit=1`, а `DIRECT_DATABASE_URL` оставьте прямым.

Все маршруты рендерятся по запросу (`force-dynamic`): каталог ингредиентов
читается из БД, и статический пререндер заморозил бы его на момент сборки.

### Работа без базы

Если `DATABASE_URL` не задан или БД недоступна, приложение **не падает**:
страницы отрисовываются, показывается явное сообщение, а движок расчёта —
чистые функции без обращений к БД — продолжает работать.

## Тесты

```bash
npm test
```

87 тестов в четырёх файлах:

* `tests/calculator.test.ts` — арифметика, масштабирование, вырожденные входы,
  отсутствие `NaN`/`Infinity`;
* `tests/excel-parity.test.ts` — **паритет с исходной книгой**: значения
  сверяются с числами, которые Excel сам сохранил в файле, до 12 знаков;
* `tests/water-activity.test.ts` — зоны, пересечения, границы, поведение
  моделей;
* `tests/shelf-life.test.ts` — контрольные точки, интерполяция, отказы,
  независимость от `a_w`;
* `tests/example-recipes.test.ts` — **подписи примеров проверяются движком**: каждая
  заявленная a_w и каждое обещанное предупреждение переcчитываются на реальной
  базе ингредиентов, поэтому подпись не может незаметно стать ложной;
* `tests/science.test.ts` — научное ядро: **валидация уравнения Норриша против
  опубликованной таблицы** (отклонение ≤ 0.0085), разложение сахаров, водная
  фаза и пределы растворимости, микробиологические пороги, барьеры, целостность
  реестров формул и источников.

Всего 212 тестов.

## Примеры с разбором

На `/recipes` доступны 10 готовых рецептур. Каждая показывает **одно** явление,
которое иначе остаётся абстракцией:

| Пример | Что видно |
|---|---|
| Тёмный ганаш 2:1 — классика | a_w ≈ 0.91: канонический ганаш не хранится при комнатной температуре |
| Сравнение сахаров ①②③ | DE 40 → 0.905, DE 60 → 0.900, инвертный → 0.891 при **одинаковой массе** добавки |
| Стабильный ганаш | a_w ≈ 0.767 — попадание в целевой диапазон 0.70–0.78 |
| Сливочный ганаш | a_w ≈ 0.97: как выглядит рецептура вне зоны стабильности |
| Пересахаренный ганаш | треть сахарозы кристаллическая и на a_w не влияет |
| Фруктовая начинка | pH 3.6 — единственный случай, где сорбат действительно работает |
| Молочный, белый ганаш | лактоза молочных сухих, сорбит, граница порога FDA 0.85 |

Все числа в подписях пересчитываются тестами против расчётного ядра.

## Лицензия и данные

Состав ингредиентов и контрольные значения срока годности принадлежат владельцу
исходной книги Excel. Значения импортированы без нормализации; строки с
неполным или противоречивым составом помечены в интерфейсе.
